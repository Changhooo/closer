执行命令：

```bash
npm run check
npm test
python -m unittest discover -s tests -v
```

真实媒体测试通过本项目 WebSocket 信令交换 SDP，实际建立 ICE、DTLS、SRTP 连接并解码媒体。输入是合成声波和动态色块，不访问真实麦克风或桌面。测试候选只使用 `127.0.0.1`，避免依赖容器网卡枚举和外网 STUN；因此这证明本机媒体传输链路，不证明跨网 NAT 穿透。

## 尚未执行

请结合 [实际设备验收清单](ACCEPTANCE.md) 验证部署环境。当前版本没有 SFU，人数增加会提高分享者上传负担。

## v1.1.0 可视化更新（2026-10-13）

新增了应用式布局、语音电平与说话指示、两套收听音量、暂停收听、实时网络卡片与曲线、专注模式、大厅创建/加入切换、帮助窗口及 PWA 安装资源。

新增验证：

本次 `npm run check` 通过，JavaScript 23 项与 Python 17 项测试均通过，共 40 项。Python 测试包含三位真实 aiortc 客户端的语音、画面、共享声音与分享者切换。

- DOM 控制器从 6 项增至 11 项：邀请默认加入与 Enter 操作、两套音量与暂停收听的边界、静音者不能显示说话、真实统计汇总、专注模式 Esc 退出、共享占用反馈。
- 音量检测 3 项：以已知波形样本检查发声/静音/短暂停顿；结束分析释放节点和动画而不停止媒体；不支持或暂停分析时不虚构音量。使用 AudioContext 测试替身，非实际设备。
- PWA 3 项：API、房间邀请、信令、第三方和带查询请求不进入缓存；更新仅删除本应用旧缓存；实际 PNG 图标尺寸、安装入口与独立窗口清单。
- 服务端新增 1 项：新资源可访问，CSP 明确允许同源 manifest 与 worker，图标类型正确。

本环境没有浏览器控制技能，未实际渲染页面、截图或测试桌面安装，也未操作浏览器授权弹窗。响应式 CSS 和可访问控件经过结构检查，实际外观仍需按验收清单检查。v1.0 的 GitHub Actions 已通过应用 Docker 构建与容器健康检查；每次推送都会自动运行包含这些检查的同一流程。
