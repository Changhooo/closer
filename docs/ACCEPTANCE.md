# 部署后验收

使用两台以上实际设备和至少三位参与者。需要能正常提供麦克风、声音播放的浏览器和 HTTPS 部署。

1. 创建房间，将完整链接发给三位朋友。每个人的成员列表应一致；达到配置人数后再加入会收到人数已满的提示。
2. 各人轮流及同时说话，其他人均应听到。戴耳机减少系统声音再次进入麦克风。
3. 一人共享含声音的视频标签页。所有其他参与者应同时收到画面与视频声音。
4. 共享者关闭语音：其他人应听不到他的麦克风，仍听到视频。重新开启语音应能恢复。
5. 共享者关闭「声音已共享」：视频声音应静音，麦克风仍正常。观看者调整音量不应影响语音。
6. 两人同时尝试共享：只允许一位取得共享权。停止或关闭浏览器共享条后，另一位能开始。
7. 分享者断开或离开后，其他人的语音连接应保留，并能由其他人接替共享。
8. 共享进行中，新成员加入，应收到当前画面及声音。另一人加入不应中断原有语音。
9. 选择低画质及高画质，检查「查看连接信息」中的实际分辨率、码率和帧率，避免只凭选项标签判断。
10. 断开一位的网络再恢复。房间服务恢复后应重新连接；长时间未恢复时使用「重新连接」。
11. 在不同运营商、移动网络等环境试用。如果直连失败，配置 coturn 并检查中继。临时设置 `RELAY_ONLY=true`，在新房间中强制验证中继路径。
12. 拒绝麦克风权限，应仍能加入和观看。未勾选标签页声音时，应显示没有捕获电脑声音的提示。
13. 离开房间后，确认麦克风和屏幕采集都结束。浏览器共享选择弹窗未完成时离开，再完成弹窗，迟到的采集也应立即停止。

记录设备型号、系统和浏览器版本、参与人数、画质、实际上传/下载、直连/中继、出现的问题。个人服务器线路与系统捕获兼容性必须使用实际部署环境判断。
